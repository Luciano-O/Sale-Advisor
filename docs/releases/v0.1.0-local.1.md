# v0.1.0-local.1

## Objetivo

Esta prerelease registra a primeira fatia vertical local do Sale Advisor para ofertas de GPUs. Ela
permite cadastrar ou importar uma mensagem no admin, preservar o dado bruto, processar e pontuar a
oferta de forma assíncrona, publicá-la no feed e consumi-la no app Android offline-first.

O fluxo entregue é:

```text
admin -> API -> raw message/outbox -> worker -> offer/score -> feed -> mobile
```

## Componentes incluídos

- monorepo pnpm com Node.js 24, pnpm 11.7, TypeScript, lint, formatação e CI;
- domínio canônico de GPUs com preço, loja, URL, deduplicação e scoring auditável;
- PostgreSQL com mensagens brutas, parses, produtos, ofertas, menções, snapshots, scores, outbox,
  instalações, notificações e eventos anônimos;
- API NestJS versionada para admin, feed, instalações, preferências amplas e eventos;
- worker NestJS/BullMQ para parsing, deduplicação, scoring, outbox e notificação;
- admin web para cadastro, importação, auditoria e correção;
- app Expo/React Native com cache, preferências locais, filtros, eventos em lote e notificações;
- jornada E2E isolada com PostgreSQL e Redis efêmeros.

## Jornada suportada

1. O admin cadastra ou importa uma mensagem de oferta.
2. A API valida o contrato e preserva a mensagem e o payload originais.
3. A transação registra um evento na outbox.
4. O worker processa a mensagem de forma idempotente, normaliza produto, loja, URL e preço,
   deduplica a oferta e cria menção, snapshot e score.
5. O feed público retorna somente o contrato consolidado, sem texto ou payload bruto.
6. O app registra uma instalação anônima, aplica preferências locais e mantém o último feed em
   cache.
7. Notificações e eventos anônimos respeitam idempotência; o provider fake é o padrão local.

## Migrations e rollback

- `0000_secret_beast.sql`: cria os enums, as 17 tabelas, constraints e índices do MVP em um
  PostgreSQL 17 vazio.
- `0001_plain_tinkerer.sql`: adiciona `offer_scores.input_hash` como nullable e o índice único usado
  na idempotência de scoring.

Compatibilidade, impacto e rollback de cada migration estão em
`packages/database/migrations/README.md`. O rollback automatizado é restrito ao banco E2E isolado e
recria somente o schema `public` após validar `NODE_ENV`, host, portas e nome do banco. Fora desse
ambiente, preservar o banco e restaurar backup é preferível a apagar dados auditáveis.

Depois do Squash and Merge, o rollback da entrega deve ser feito em um novo Pull Request com
`git revert <commit-do-squash>`.

## Instalação e homologação

Pré-requisitos: Windows 11, Docker Desktop com backend Linux, Node.js 24.x e Corepack. Para o aceite
Android, também são necessários JDK 21, SDK/API 36, build-tools 36 e um device ou emulador API 36.

```powershell
Copy-Item .env.example .env
corepack enable
corepack pnpm install --frozen-lockfile
powershell -ExecutionPolicy Bypass -File .\infra\bootstrap.ps1
corepack pnpm verify:baseline
```

O aceite manual Android e a matriz executada estão em `docs/mvp-local-runbook.md`.

## Limitações conhecidas

- sem coleta ou integração com Telegram;
- adaptadores e fixtures de loja são demonstrativos;
- FCM real é opcional e exige credenciais externas não incluídas;
- sem login ou sincronização de preferências finas;
- sem deploy público;
- sem publicação em loja;
- sem scraping ou resolução de encurtadores.
